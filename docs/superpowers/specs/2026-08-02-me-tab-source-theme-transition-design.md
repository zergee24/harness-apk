# “我的”Tab 来源主题继承与平滑过渡设计

日期：2026-08-02

## 1. 决策状态

本设计调整三 Tab 首页的主题归属：`我的` 不再拥有固定主题，而是继承用户进入它之前所在的业务 Tab 主题。

- `生活 -> 我的`：继续使用暖浅主题。
- `工作 -> 我的`：继续使用深科技主题。
- `我的 -> 生活/工作`：以目标业务 Tab 为准切换主题。
- 应用重启后若仍停留在 `我的`，继续恢复最近一次生活或工作主题。
- 旧安装没有来源记录时，默认使用生活主题。

同时将主题过渡从仅颜色的 300ms 动画，调整为颜色与组件圆角协同的约 450ms 缓入缓出动画。

## 2. 问题定义

当前 `ModeTheme` 直接将 `ME` 映射为深科技主题，导致用户从生活进入“我的”时界面突然由浅色变成深色。“我的”是设置聚合页，不代表独立业务语境，固定深色会割裂来源体验。

现有过渡还存在两个不一致：

1. 所有颜色使用 300ms `tween`，浅色与深色之间变化过快。
2. `Shapes` 在 `HarnessShapes` 与 `TechShapes` 之间瞬间切换，颜色仍在动画时圆角已经跳到终态。

## 3. 目标与边界

### 目标

1. “我的”视觉主题跟随最近访问的生活或工作 Tab。
2. 来源主题能够跨进程恢复。
3. 生活与工作直接切换时，颜色和组件形状连续变化。
4. 不改变三 Tab 的导航结构、页面内容与返回行为。

### 非目标

- 不新增第三套主题。
- 不让“我的”影响生活或工作的业务状态。
- 不为页面内容增加位移、缩放或整页交叉淡入动画。
- 不改动设置子页面、项目工作台或会话列表结构。

## 4. 状态设计

### 4.1 当前 Tab 与主题来源分离

保留 `mainMode: MainMode` 表示底部导航当前选中项，新增 `themeSourceMode: MainMode` 表示最近的业务主题来源。`themeSourceMode` 只允许 `LIFE` 或 `WORK`。

主题解析规则集中为纯函数：

```text
resolveThemeMode(mainMode, themeSourceMode)
  LIFE -> LIFE
  WORK -> WORK
  ME   -> normalized(themeSourceMode)
```

`normalized` 将非法的 `ME` 或缺失值回退为 `LIFE`，避免主题状态出现第三种语义。

### 4.2 Tab 点击规则

- 点击 `LIFE`：同时设置 `mainMode=LIFE`、`themeSourceMode=LIFE`。
- 点击 `WORK`：同时设置 `mainMode=WORK`、`themeSourceMode=WORK`。
- 点击 `ME`：只设置 `mainMode=ME`，保留 `themeSourceMode`。
- 代码内部跳转到工作台时：同时设置 `mainMode=WORK`、`themeSourceMode=WORK`。

`ModeTheme` 接收解析后的有效主题模式，不直接根据 `ME` 决定颜色。

### 4.3 持久化与迁移

`HomeModeStore` 在现有 `main_mode` 之外增加 `theme_source_mode`：

- 保存 `LIFE/WORK` 时，同时更新来源。
- 保存 `ME` 时只更新当前 Tab，不覆盖来源。
- 加载来源时仅接受 `LIFE/WORK`；缺失、未知值或 `ME` 均回退为 `LIFE`。
- `reset()` 同时清除两个字段，测试与旧数据迁移行为保持确定。

## 5. 主题动画

### 5.1 动画规格

- 时长：450ms。
- 缓动：`FastOutSlowInEasing`。
- 同一 `Transition` 同步驱动全部颜色与圆角，避免每个状态动画启动时点不一致。
- 生活进入“我的”或工作进入“我的”时有效主题不变，因此不触发主题动画。

### 5.2 颜色

保留现有暖浅与深科技 `ColorScheme`，只替换动画组织方式。颜色值不在本次调整范围内。

### 5.3 圆角

对 `Shapes` 的五档圆角半径进行插值，并在每帧重建 `Shapes`：

- 暖浅：8 / 10 / 14 / 18 / 22 dp。
- 深科技：4 / 6 / 8 / 10 / 12 dp。

这样浅色与深色切换时，卡片、输入框和容器边角与颜色同步收紧或放松，不再瞬间跳变。

## 6. 测试策略

### JVM 单测

- `ME + LIFE source -> LIFE theme`。
- `ME + WORK source -> WORK theme`。
- 非 `ME` Tab 始终使用自身主题。
- 来源迁移只接受 `LIFE/WORK`，其他值回退 `LIFE`。
- 保存 `ME` 不覆盖最近来源。

### Compose 测试

- 生活点击“我的”后背景保持暖浅。
- 工作点击“我的”后背景保持深科技。
- 生活与工作切换结束后颜色和圆角都到达目标值。

### 回归验证

- 运行 `:app:testDebugUnitTest` 与 `:app:assembleDebug`。
- 在模拟器检查生活、工作、我的三条切换路径，确认无闪白、无文字与背景短暂低对比、无布局跳动。

## 7. 风险与对策

| 风险 | 对策 |
|---|---|
| `ME` 被误写为主题来源 | 统一通过规范化纯函数处理，持久化层拒绝 `ME` |
| 当前 Tab 与来源保存时序不一致 | `HomeModeStore` 提供单一保存入口，在同一次编辑中更新相关字段 |
| 动画期间文字对比不足 | 同一 Transition 同步动画成对的前景色和背景色 |
| 圆角插值导致过多重组 | 仅在主题切换的 450ms 内重组，范围限定在根 MaterialTheme |
| 进程恢复到“我的”时主题错误 | 当前 Tab 与来源分别持久化，加载时独立迁移 |
