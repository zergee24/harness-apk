# 项目交付物层与入口收敛设计：Git 降级为取证底座，远程/副屏入口合并

## 1. 决策摘要

工作模式当前把四类不同性质的能力并排放在用户可见拓扑里：会话、文件夹、Git、远程（含副屏）。本设计收敛为两层：

1. **用户可见层只保留一种一等对象：项目交付物（Deliverable）。** 会话沉淀文件、将来的工作简报、Run 证据链接都归属这一层；Git 不再是与之并列的常驻 Tab，降级为交付物层**下面的快照与取证底座**，只在四个情境点露出。
2. **工作模式顶栏的远程能力从双入口收敛为单入口。** 「远程」「副屏」合并为一个「远程」Hub 入口，副屏成为 Hub 内的一个模式；设置页保留节点配置与副屏快捷方式。

Git **数据层完整保留**（JGitEngine 能力、白名单提交、非快进禁推、Apply 不自动 commit 等安全纪律一项不减）。收敛的只是它的**管理界面**。

## 2. 背景与问题：现状入口盘点

2026-09-03 审计的入口全量清单：

| # | 入口 | 位置 | 触发条件 | 去向 |
| --- | --- | --- | --- | --- |
| 1 | 「远程」 | 工作模式顶栏（`HarnessApkApp.kt:466`） | `remoteProfile != null` | RemoteControl 线程控制页 |
| 2 | 「副屏」 | 工作模式顶栏（`HarnessApkApp.kt:468`） | WORK 模式常驻 | DashboardActivity |
| 3 | 「副屏模式（常亮）」 | Codex 远程节点设置页（`RemoteSettingsScreen.kt:133`） | 已配置节点 | DashboardActivity |
| 4 | Git Tab | 项目工作台第三 Tab（`ProjectUiState.kt:12`） | 常驻 | `ProjectGitPanel`：分支/干净度/领先落后 chips + 待提交/提交全部/推送/Fetch/快进拉取/新建分支按钮 + 5 个对话框 |
| 5 | 「查看文件」「查看 Git 变更」 | 会话文件变更结果卡 | 文件变更应用后 | Workbench target（CONVERSATIONS/FILES/GIT） |

问题：

1. **Git Tab 是低频 power-user 面却占据高频位。** 分支管理、Fetch、快进拉取是周级低频操作，却与会话、文件夹并列常驻一个 Tab。日常真正需要的是"有没有未提交变更 + 一键提交"，这一件事占了整个 Tab。
2. **远程是一件事，入口拆在三处。** 线程控制（顶栏→RemoteControl）、副屏挂机（顶栏）、副屏模式（设置页）指向同一个远程工作流，用户要理解三个入口的分工。
3. **简报将再加一物体。** 简报 spec（2026-08-19）已刻意"不增加工作台 Tab"，把 `WORK_BRIEF` 塞进文件夹；但如果 Git Tab、双远程入口不先收敛，工作台的信息密度会继续恶化，简报只是压垮入口的下一根稻草。

## 3. 目标与非目标

### 3.1 目标

1. 项目工作台用户可见的一等对象只有**交付物**；工作台 Tab 从 3 个收敛为 2 个（会话 / 文件夹）。
2. Git 从常驻 Tab 降级为底座，只在 4 个情境点露出（见 5.2）。
3. 工作模式顶栏远程相关入口从 2 个收敛为 1 个；副屏不再独立占位。
4. 建立统一的**锚点与证据服务**协议，供简报、M3 沉淀、完成卡、会话引用回跳共用（见 5.3）。

### 3.2 明确非目标

1. 不削减 Git 数据层能力与安全纪律：白名单提交、自动提交信息、提交后单独确认推送、非快进禁推、Apply 永不自动 commit/push、锁屏通知不批准 Git 操作——全部原样保留。
2. 不做通用文件同步；跨设备传输仍是显式导入 / Git Fetch / 受控任务（product-plan v5 边界不变）。
3. 不动生活模式；双模式首页结构不变。
4. 不在本 spec 内定义简报的画布、录音、时间轴细节（沿用 2026-08-19 spec）。
5. 不删除 `GitSettingsScreen`（节点/仓库级 Git 配置仍是合法的设置场景）。

## 4. 分层模型

```text
┌─ 用户可见层 ────────────────────────────────┐
│  项目交付物：文件（MD/Office/PDF）· 工作简报  │
│  · Run 证据链接（候选，P2）                  │
│  会话 / 远程 Hub / 通知 作为并行的一级入口    │
├─ 锚点与证据服务（协议层）──────────────────┤
│  统一锚点模型：定位 + 内容哈希 + 可选快照 ID  │
├─ 快照与取证底座（实现层）──────────────────┤
│  Git（JGitEngine）· .hbrief 封存 · Run/Evidence Snapshot │
└────────────────────────────────────────────┘
```

原则：**用户引用的永远是"不可变快照"，不是活状态。** 交付物层的任何引用（简报标记、M3 沉淀、完成卡证据）经锚点服务解析到底座的某个快照；底座可以有多种实现，Git 是文件类交付物的那个实现。

## 5. 具体设计

### 5.1 交付物层

- `ProjectArtifactType` 扩展 `WORK_BRIEF`（沿用简报 spec 6.1 的决定），后续 `RUN_EVIDENCE` 为候选。
- 文件夹 Tab 即交付物层的主视图：树/筛选/排序逻辑不变，简报作为新类型自然进入，列表行按类型展示自有元信息（简报：总记录时长、音频可用状态、未处理标记数）。
- 交付物详情按类型分派：文件→预览/编辑；简报→原生回放页（`.hbrief`）。

### 5.2 Git 降级：4 个情境露点 + 1 个低频后台

Git Tab（`ProjectGitPanel` 常驻面板）取消，替换为：

1. **变更条（文件夹页顶部）**：有未提交变更时显示"N 个未提交变更 · 分支名"，点开展开 diff 摘要与「提交」「推送」动作；工作区干净时不占位。这是日常主露点，承接原 Git Tab 90% 的使用。
2. **交付物详情·历史**：单个文件详情内提供"历史"，按需查看该文件的 commit 列表与 diff。
3. **锚点选择器**：简报/M3 引用代码证据时的 commit/diff 选择视图（协议见 5.3）。
4. **结果卡跳转**：会话"查看 Git 变更"target 保留，重定向到文件夹页并自动展开变更条（`ProjectWorkbenchDestination.GIT` 语义保留、落点改变）。

分支管理（新建分支、checkout、克隆、初始化、绑定 remote）整体移入**项目设置 · Git**（并入或紧邻 `GitSettingsScreen`），与 push/fetch 凭据配置同处一个低频场景。非快进禁推等纪律的报错引导指向该页。

### 5.3 锚点与证据服务（协议层）

对齐简报 spec 5.5，全 App 唯一锚点模型：

```kotlin
data class ProjectEvidenceAnchor(
    val type: AnchorType,          // PROJECT_FILE / FILE_RANGE / DIFF / COMMIT / TEST_EVIDENCE
                                   // / RUN_EVENT / RUN_COMPLETION / SCREENSHOT_REGION
    val projectId: String,
    val relativePath: String?,     // 项目相对定位
    val contentHash: String,       // SHA-256，必填
    val gitRef: String?,           // 可选 commit id / blob hash
    val runSnapshotId: String?,    // 可选，M2/Evidence Snapshot
    val excerpt: String?,          // 小型摘录，禁止整文件
)
```

硬约束（继承简报 spec 5.5）：不保存带凭证 URL、Mac 用户目录前缀或完整工作区副本；锚点只解析到不可变快照，底座状态变化不改写已创建的锚点。

消费方与时序：**简报 P0 是首个消费方**（用户标记锚定代码证据）；完成卡证据、M3 沉淀引用、会话回跳随后迁移到同一协议。

### 5.4 远程与副屏收敛

现状三入口（盘点 #1/#2/#3）收敛为：

```text
工作模式顶栏：「远程」×1（保留 remoteProfile != null 条件）
  └→ 远程 Hub（现 RemoteControl 页升级）
       ├ 线程列表 + 控制（现状不变）
       └ 顶部常驻「副屏模式」入口 → DashboardActivity（全屏，系统返回退出）
设置 · Codex 远程节点页：保留「副屏模式（常亮）」快捷方式（配置场景就近直达）
顶栏「副屏」独立按钮：移除
```

决策理由：副屏的高频场景是"上架后整晚常亮挂机"，进入后是长驻状态而非频繁往返，从顶栏直达的收益低于一个常驻入口的整洁收益；挂机启动路径为 顶栏「远程」→ Hub →「副屏模式」两步，与原设置页路径同深。**备选**（实施时按真机习惯验证）：若挂机启动频率证明两步过重，将 Hub 的副屏入口提升为 Hub 顶排第一个大按钮，或给 DashboardActivity 注册桌面快捷方式（long-press app icon 直达），不在顶栏回收入口。

### 5.5 信息架构变化明细

| 对象 | Before | After |
| --- | --- | --- |
| 工作台 Tab | 会话 / 文件夹 / Git | 会话 / 文件夹 |
| Git 日常操作 | 独立 Tab 常驻 | 文件夹页变更条（情境露出） |
| 分支/克隆/初始化 | Git Tab | 项目设置 · Git |
| 工作模式顶栏 | 远程 + 副屏 + 通知铃 | 远程（Hub） + 通知铃 |
| 副屏入口 | 顶栏 + 节点设置页 | 远程 Hub + 节点设置页 |
| 简报（新增） | — | 文件夹内交付物类型，无新 Tab、无新顶栏入口 |
| 会话结果卡「查看 Git 变更」 | → Git Tab | → 文件夹页 + 自动展开变更条 |

## 6. 与可回放工作简报 P0 的关系

1. **落点约束**：简报实施必须落在交付物层与锚点服务上——`WORK_BRIEF` 走 `ProjectArtifactType` 注册，代码锚点直接采用 5.3 协议；锚点协议由本 spec 定稿，简报 P0 作为首个消费方定稿细节（类型枚举是否需要裁剪、excerpt 上限等）。
2. **时序**：两条线互不阻塞。入口收敛（5.2/5.4）是纯 UI 移位，可先行或并行；锚点服务协议随简报 P0 落地。若入口收敛先完成，简报的次级入口（会话更多菜单、Run 完成卡）直接按新 IA 实现，避免二次迁移。
3. **简报 P0 不等待本 spec 的 P1**（交付物详情统一），回放页按简报 spec 独立实现即可。

## 7. 实施包

### P0-A 入口收敛（纯 UI 移位，先行）

- 工作台 Git Tab 移除；变更条组件上文件夹页；分支管理等并入项目设置·Git。
- 顶栏移除「副屏」，RemoteControl 页加副屏模式入口。
- `ProjectWorkbenchDestination.GIT` 重定向；结果卡文案与跳转回归。
- 验收：工作台 Tab = 2；顶栏远程相关按钮 = 1；既有 Git 流程（提交/推送/非快进拒绝）在变更加与设置页各回归一遍；`:app:testDebugUnitTest` 全量通过。

### P0-B 锚点服务协议（随简报 P0）

- `ProjectEvidenceAnchor` 模型 + 存取 API + 单测（哈希、禁存字段校验、快照不可变解析）。
- 首个消费方为简报用户标记；完成卡/M3 迁移另行排期。

### P1 交付物详情统一

- 文件详情内嵌"历史"（Git log 按文件过滤）；简报回放页接入同一详情骨架。

### P2 候选

- Run 证据链接作为交付物类型进入文件夹；锚点选择器统一组件化。

## 8. 兼容与迁移

1. 现有 `.git` 仓库、凭据（`GitCredentialStore`）、`JGitEngine` API 零改动；本 spec 不产生 Room 迁移（交付物层复用现有存储；锚点服务若需落库，随简报 P0 的 Room 版本一起编号）。
2. `ProjectWorkbenchTab.GIT` / `ProjectWorkbenchDestination.GIT` 枚举值保留（避免 target 反序列化/测试断言破裂），语义改为"文件夹+变更条"。
3. `Routes.RemoteControl`、`DashboardActivity` 路由不变，仅入口增减。

## 9. 开放问题

1. 副屏两步启动是否过重——待副屏整晚挂机验收（dashboard Task 9 Step 4）后按真实使用频率决策 5.4 的备选方案。
2. 变更条与文件写入的并发呈现：Agent 批量写文件进行中时，变更条是否显示"应用中"态，还是仅在应用完成后出现（倾向后者，避免与结果卡重复）。
3. 简报列表行与文件列表行的元信息合并规则（简报的"未处理标记数"是否进筛选器）。
