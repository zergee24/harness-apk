# Harness 双模式首页与双主题设计

日期：2026-08-01

## 1. 决策状态

本设计把首页从平级三 Tab（会话 / 项目 / 远程）重构为**生活 / 工作双模式**，用左右滑动 + 顶部 Tab 切换，并让两模式各自拥有独立的 Material3 主题。

本设计确认以下产品关系：

- 产品是**自用为主**的移动端个人 AI 工作台，覆盖两种使用模式：生活（知识工作流）与工作（项目 + 桌面端协作）。
- **底层能力是横切的**：模型/Provider、会话引擎、智能体、Wiki 知识包、搜索/语音/技能、写回/审核、远程控制、自更新均为模式无关能力，不因模式分裂。
- **模式层只决定首页聚合视角**：生活 = 按会话聚合，工作 = 按项目聚合。
- 所有既有能力全部保留，不砍功能，只重排层级与入口。
- 双主题固定两套：生活 = 暖浅主题，工作 = 深科技主题；不跟随系统深浅，不做四档组合。
- 模式切换持久化：启动恢复上次所在面板，不固定回落生活。
- 本次改动边界：只动 UI 导航层与主题层，能力层（仓库、引擎、服务）零改动。

## 2. 问题定义

当前首页 `MainMode` 为三个平级 Tab：会话 / 项目 / 远程（`HomeUiState.kt`）。平级结构导致主次不分：

- 生活侧能力（普通对话、智能体、Wiki 检索引用）全部挤在"会话"一个 Tab 里，页面过满。
- 工作侧能力被拆成"项目"与"远程"两个平级 Tab，工作模式四分五裂。
- 三个 Tab 地位相等，无法表达"随手问答"与"推进项目"两种真实使用状态的区别。

产品计划（`docs/product-plan.md`）与真实开发重心已脱节：实际重心是智能体人格、知识包检索、远程控制，而计划文档仍以"项目工作台闭环"为主线。需要以**双模式叙事**重新对齐定位。

## 3. 产品目标

### 3.1 目标

1. 首页提供生活 / 工作两个聚合视角，左右滑动 + 顶部 Tab 切换，切换成本趋近于零。
2. 生活模式呈现会话聚合视角：最近会话、智能体选择、知识库入口，支持随手问答与研究。
3. 工作模式呈现项目聚合视角：项目列表、项目工作台（会话/文件夹/Git）、远程控制入口。
4. 生活使用暖浅主题（奶油暖色、大圆角），工作使用深科技主题（石墨深色、锐利小圆角），主题随模式落定后切换，全 App 页面统一跟随。
5. 启动时恢复上次面板；进程内切换状态用 `rememberSaveable` 保留。
6. 智能体、Wiki、模型、会话等底层能力在所有模式下可用，入口与挂载点不因模式变化。

### 3.2 成功标准

- 一次滑动即可在两种工作状态间切换，主题过渡不闪烁、不突兀。
- 生活面板默认落点清晰（会话），工作面板默认落点清晰（项目），不再有三个平级入口的困惑。
- 现有能力（项目工作台、Wiki 检索、智能体挂载、远程控制、自更新）全部可用，无功能回归。
- 旧持久化状态（REMOTE）能安全迁移，不崩溃、不丢设置。
- 模式选择在进程重启后保持。

## 4. 非目标

本次设计不包含以下内容：

- 不新增第三、第四个模式；不把知识库、智能体做成独立顶层模式。
- 不跟随系统深浅色；不提供"双主题各自深浅四档"。
- 不重构 Chat、Wiki、Settings、RemoteSettings 等子页面结构。
- 不改动任何能力层代码（会话引擎、Wiki 检索、远程服务、更新链路）。
- 不做滑动过程主题实时渐变（第一期落定切换，后续按需迭代）。
- 不做云同步、多用户、账号体系。

## 5. 设计

### 5.1 结构层：双模式 + Pager 首页

```
MainMode: SESSION / PROJECT / REMOTE      →      MainMode: LIFE / WORK
                 ▼                                    ▼
    首页三选一（底部 NavigationBar）        首页双面板（HorizontalPager 左右滑动）
                                          ┌─────────────┬─────────────┐
                                          │   生活面板   │   工作面板   │
                                          │ 会话列表     │ 项目列表     │
                                          │ ·智能体入口  │ ·远程入口    │
                                          │ ·知识库入口  │ ·Git 工作台  │
                                          └─────────────┴─────────────┘
                                             顶部 Tab：生活 | 工作（可点击）
```

- `MainMode` 重定义为 `LIFE / WORK`，`HomeUiState.kt` 中的枚举、`topLevelTitle`、`homePrimaryAction` 同步修改。
- 首页（`Routes.Conversations`）改为 `HorizontalPager` 双面板 + 顶部 SegmentedTab；移除底部 NavigationBar。
- 面板落定（`settledPage`）后提交模式状态，避免滑动过程中模式抖动。

### 5.2 能力层：横切，模式无关

```
┌─────────────────────────────────────────────┐
│  模式层（只决定首页聚合视角）                   │
│  生活：会话聚合        工作：项目聚合           │
└─────────────────────────────────────────────┘
                    ▲ 横切引用
┌─────────────────────────────────────────────┐
│  底层能力层（模式无关，任何会话/项目内可挂载）    │
│  模型/Provider │ 会话引擎 │ 智能体 │ Wiki 知识包 │
│  搜索/语音/技能 │ 写回/审核 │ 远程控制 │ 自更新    │
└─────────────────────────────────────────────┘
```

| 能力 | 挂载点（不因模式变化） |
|---|---|
| 智能体 | 会话内选择人格（现有）+ 设置页全局管理 |
| Wiki 知识包 | 会话内检索/引用（现有）+ 设置页库管理 |
| 模型 | Provider 配置，全局 |
| 远程控制 | 全局能力，工作面板提供入口卡片 |

### 5.3 主题层：暖浅 / 深科技双主题

| | 生活模式 | 工作模式 |
|---|---|---|
| 色彩 | 奶油/米色底、暖橙主色、柔和高亮 | 石墨黑/深蓝底、青白主色、锐利高亮 |
| 形状 | 大圆角卡片（16-24dp） | 小圆角（4-8dp） |
| 氛围 | 温馨、柔和 | 科技、简约 |

- 新增两套 Material3 `ColorScheme` + `Shapes` 定义（`ui/theme/`）。
- 应用入口按 `MainMode` 选择主题：`MaterialTheme(colorScheme = if (LIFE) warmLight else techDark, shapes = ...)`，全 App 页面统一跟随。
- 切换时机：滑动松手、面板落定后切换，带约 300ms 颜色/形状过渡动画。
- 启动按恢复的模式直接着色，避免闪屏。

### 5.4 面板内容组织

**生活面板（会话聚合视角）**
- 主体：现有 `ConversationListScreen`，默认"最近会话"视图（"按项目分组"视图保留）。
- 顶部快捷入口行：智能体（挂人格）、Wiki 知识库（进全局管理页）。
- FAB 新建会话（现有）。

**工作面板（项目聚合视角）**
- 主体：现有 `ProjectScreen` 原样保留（项目列表 → 项目工作台：会话/文件夹/Git）。
- 顶部卡片：远程控制入口（显示节点状态；`remoteProfile` 为空时隐藏，沿用现有兜底逻辑）。
- 新建项目（现有）。

**横切入口不重复建设**：智能体包管理、Wiki 库管理仍在设置页，面板顶部入口仅为快捷跳转。

### 5.5 模式持久化

- 用 SharedPreferences 保存 `MainMode`（不引新依赖），启动时恢复，切换时写回。
- 旧值迁移：三态时代的 `REMOTE` 映射为 `WORK`；`SESSION`/`PROJECT` 分别映射为 `LIFE`/`WORK`，写迁移函数保证向后兼容。
- 进程内切换状态用 `rememberSaveable` 保留（现有机制沿用）。

## 6. 技术落地清单

改动文件（能力层零改动）：

| 文件 | 改动 |
|---|---|
| `ui/HomeUiState.kt` | `MainMode` 重定义 LIFE/WORK，辅助函数同步 |
| `ui/HarnessApkApp.kt` | 首页改 Pager 双面板、顶部 Tab、移除底部 NavigationBar、主题按模式切换、模式持久化读写 |
| `ui/theme/` | 新增暖浅/深科技两套 ColorScheme + Shapes |
| `ui/conversation/ConversationListScreen.kt` | 顶部快捷入口行（智能体/Wiki） |
| `ui/project/ProjectScreen.kt` | 远程控制入口卡片 |
| 新增：模式持久化仓库（SharedPreferences 封装 + 迁移） | 读写与迁移函数 |

不动：`ChatScreen`、Wiki 全部页面、Settings 全部页面、`RemoteScreen`（逻辑并入入口卡片或保留 route）、能力层所有模块。

## 7. 测试与验收

- 单测：三态→双态迁移、持久化读写、`HomeUiState` 纯函数。
- Compose 测试：Pager 切换、主题切换后关键色值断言、远程入口可见性（有/无 profile）。
- 回归：`HarnessApkAppNavigationTest` 适配新导航结构；现有 `HomeModeUiStateTest` 同步更新。
- 真机验收：
  1. 左右滑动切换两面板，松手落定主题过渡平滑。
  2. 重启 App 恢复上次面板。
  3. 从旧版本升级（持久化 REMOTE 等旧值）不崩溃、模式正确。
  4. 项目工作台、Wiki 检索、智能体挂载、远程控制、自更新全部可用。

## 8. 风险与对策

| 风险 | 对策 |
|---|---|
| 三态→双态迁移破坏旧数据 | 迁移函数 + 单测覆盖 REMOTE/SESSION/PROJECT 三种旧值 |
| Pager 滑动与导航冲突 | 首页 route 不变，子页面导航不动，仅首页内部重组 |
| 主题切换闪屏 | 落定后切换 + 300ms 过渡，启动按恢复模式着色 |
| 双主题增大维护面 | 只维护两套色板与形状，字体/间距共用现有 token |
