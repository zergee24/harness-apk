## 1. 结论

HiBreak 电纸书 + 自带手写笔**满足进入 P1（本地简报核心）的输入条件**：

1. 手写笔能力真实可用——压感与 tilt 均为触控硬件上报（非注入/恒定值）；
2. 墨水预览管道延迟健康（事件→绘制 p50 12~21ms / p95 22~27ms）；
3. 点级擦除、压感变宽、JSONL 追加日志、强杀恢复全部真机验证通过；
4. 书写过程手指零混入（24 笔全为 stylus，掌搭无污染）。

e-ink 面板物理刷新是"跟笔"的剩余上限，属于设备特性而非管道缺陷；缓解路径见 §4。

## 4. 跟笔（e-ink 残余风险与缓解）

事件管道健康，"不跟笔"的剩余部分来自 e-ink 面板刷新。已落地缓解：离屏位图缓存 + 局部失效（触摸只重绘笔尖矩形，触发面板局部快刷），统计条移出画布。建议叠加：

1. 系统层：Bigme 控制中心把本 App 的墨水屏刷新模式调至最快档（A2/高速）；
2. 代码层候选（P1 时再做）：笔迹预测（按速度外插一段）、压感线宽的 e-ink 抖动评估（反锯齿灰边可能拖慢刷新）。

## 6. AI 可读性验证（P1 启动前专项，2026-09-04）

方法：将真实书写的 `strokes.jsonl` 按 App 同语义重放（笔画 + 点级擦除）渲染成 PNG，由多模态模型直接读图识别。

结果：

- **原始 JSONL（坐标+压感点集）对 AI 不可读**——语义不在数字里，在几何形状里；LLM 无法从点集直接认出内容。
- **渲染成图后：数字可读、汉字不可靠**——手写数字 `123 456 789.` 完整准确识别；"一"置信度中等（55~65%）；连笔汉字（"马"）置信度仅 ~30%，连笔草书与画图只能判为图形（~~初稿曾写"简单汉字可辨"，经第三方模型联合测试修正~~）。

### 第二轮：第三方模型（GPT）联合实测（2026-09-04）

方法：按 §14.2 组装真实 AI 输入包（元信息 + ⟦B1:P1⟧ 画布 2× 裁剪渲染 PNG + 如实标注缺失层），交由 GPT 多模态模型按三档任务实测（认字 → 结构化纪要 → 北极星恢复）。

结果：

| 任务 | 结果 | 说明 |
| --- | --- | --- |
| 认字基线 | **通过** | 数字行 98% 完整准确；2× 裁剪渲染足以承载该尺寸清晰笔迹 |
| 防幻觉 | **通过** | 正确区分文字/标点/自由涂画，拒绝把波浪线补全成词句 |
| 结构化纪要 | 本样本不可验证 | 样本无工作语义，生成具体决策/待办即构成编造（模型正确拒绝） |
| 北极星恢复 | 本样本未通过 | 瓶颈是**缺少语义层（标记/转写/上下文）**，不是图片清晰度 |

Caveat：本会话中人工基线（"写了 123456789"）已在对话中向模型透露，非严格盲测；本结果记为**可行性样本**。"AI 可读路线稳定"的结论需用一张未向模型公开标准答案的真实工作页复测后再下。

P1 判断修正：当前样本不支持把"提高分辨率/拆页"列为修复项；真正的语义缺口在标记层（P1 范围）与转写层（P2 范围）——**画布视觉通道按现状（2× 渲染）即可进入 P1**，北极星指标的关键路径在语义层而非渲染保真度。

结论与要求：

1. raw strokes 是**保真层**（回放/法律效力用），不是 AI 消费层；
2. P1 数据模型必须把**每页渲染 PNG 作为封存时自动生成的派生产物**（Bundle 建议 `preview/pages/<pageId>.webp`），AI 纪要与检索只消费渲染图 + 转写 + 标记，不消费点集；
3. HWR（手写识别转文字）按范围熔断暂不做，作为后续可选增强。
