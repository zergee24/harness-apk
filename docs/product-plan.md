## 产品定位

Harness APK 是一个**自用为主**的移动端个人 AI 工作台，覆盖两种真实使用模式：

- **生活模式**：知识工作流。带智能体人格的对话、离线知识包（hwiki）检索与引用，随手问答、研究与写作。
- **工作模式**：项目 + 桌面端协作。项目会话、Markdown 文件变更审核与写回、Git 状态，以及手机遥控桌面 Codex 的远程控制。

产品不定位为通用聊天应用，不追求社交、账号、云端协同或应用商店分发。**底层能力是横切的**：模型/Provider、会话引擎、智能体、Wiki 知识包、搜索/语音/技能、写回/审核、远程控制、自更新均为模式无关能力，任何会话/项目内可挂载；模式层只决定首页聚合视角（生活=按普通会话聚合，工作=按项目聚合）。

**护城河（不变）**：外部生态（开源 trending、豆包/方舟等平台）都在向"更广、更自动、平台代执行"加速；Harness 的差异化是反方向——**移动端、本机、每步可见、每步确认**。路线图不追广度，只做深受控闭环。详见 `docs/agent-landscape-2026-08-04.md`、`docs/rikkahub-comparison-2026-07-10.md`（两文顶部已标"已被本文取代"，保留作历史）。

## 导航结构（0.2.4 现状）

- 一级导航为**底部三 Tab：生活 / 工作 / 我的**（Material3 NavigationBar）；旧的顶部模式 Tab 与 HorizontalPager 滑动面板已移除。
- **生活 Tab** = 普通会话列表（`projectId == null`，UI 上隐藏"默认生活项目"层级）+ 智能体/知识库快捷入口 + 新建会话 FAB；不出现任何项目概念（分组、文件夹、工作台）。
- **工作 Tab** = 远程控制入口卡片（配对后可见）+ 项目列表 + 项目工作台（项目会话/文件夹/Git）。
- **我的 Tab** = 设置聚合页（内嵌 SettingsScreen）；顶栏设置按钮已移除。
- 双主题：**生活=暖浅；工作、我的=深科技**，300ms 颜色过渡，全 App 统一跟随。
- 模式持久化：启动恢复上次 Tab；旧值迁移（LIFE→LIFE、WORK→WORK）。
- 主要能力挂载点：智能体=会话内选择人格 + 我的 Tab 全局管理；Wiki 知识包=会话内检索/引用 + 我的 Tab 库管理；远程控制=全局能力，工作 Tab 提供入口。

## 当前状态（0.2.4）

### 已具备能力

- 多会话聊天、本地保存、流式回复、图片附件、上下文压缩、联网搜索。
- 智能体体系：Agent Builder 打包人格/语料 `.hbundle`、签名校验、安装管理、删除解关联；李德胜 V2 可检索智能体（balanced `.hbundle`，侧载导入）。
- hwiki 知识包体系：双史书（二十四史/资治通鉴）离线检索、Markdown 脚注引用、证据校验（`WikiCitationVerifier`）、原文快照防漂移、版本管理。
- 项目工作台：项目会话、Markdown 文件变更计划/审核/写回、文件预览、PDF 导出、ZIP 导入导出、Git 状态面板。
- Codex 远程控制：私有 relay/bridge、配对加密、消息确认、退避重连、审批选项。
- 三 Tab 底部导航 + 双主题（0.2.4，已发 test，待真机回归）。
- APK 更新检查、分片下载、SHA-256 校验、安装；测试/正式通道分离；manifest `minSupportedVersionCode` 支持 `forceUpdate`。

### 主要缺口（按优先级分组，已对代码核实）

**P0 闭环（代码级，逐项核实仍开放）**
- 写回项目后 Git 状态不自动刷新：`ChatScreen.kt:1287-1353` apply 路径只刷新会话内 deliverables，Git tab 仅在进入时读 `git status`。
- 项目上下文无 UI 展示 / 当前项目无常驻 Chip：项目名仅在工作首页标题（`topLevelTitle`）和 SessionConfigDialog 内出现，会话输入栏与会话列表均无。
- 安装取消无反馈：`ApkInstaller.kt` 仅构造 `Intent(ACTION_VIEW)`，经 `startActivity` fire-and-forget，无安装结果回调。
- WORK/我的 深色主题下系统状态栏图标对比度未联动：`Theme.kt`/`MainActivity.kt` 不碰 system bar，靠 `values/values-night` 按系统深色模式，导致深色 App 主题 + 浅色系统时状态栏图标深色不可见。

**P0 收尾（流程）**
- 0.2.4 真机回归未完成：三 Tab 切换、双主题过渡、重启恢复 Tab、远程入口、生活会话列表无项目分组等，androidTest 需在设备补跑。
- 发布节奏未固化：曾出现"版本号预约给某里程碑、却被其它工作占用"的漂移（0.2.4 原预约给 P0 闭环增强，实际被三 Tab 导航占用）。v4 起以"发布前收口 checklist"约束（见优先级原则）。

**P1 工作线（Git 闭环未真正闭合）**
- Git 仍是"只读状态查看 + 手动跳转"：手机上不能把刚评审通过的写回落地为提交，项目写回闭环止于"看 status"。

**横切能力**
- 远程控制缺真机回归与可靠性验证（横切能力，不绑工作线，与 P3 一并维护）。

## 阶段目标

### P0：稳定可用闭环 + 三 Tab 收口（进行中，0.2.5）

在真实 Android 设备上稳定完成一次完整工作流：创建/导入项目 → 新建项目会话 → LLM 生成或更新 Markdown → 审核 diff 并写回 → 文件夹查看结果 → Git 状态 → 自更新获得新版本；并补齐三 Tab 导航的真机回归。0.2.5 专门闭合四个代码级 P0 缺口。

### P1：工作模式 Git 闭环（受确认的原生提交/推送）

把项目写回闭环**真正闭合**：手机上把"本轮已评审并 apply 的写回文件"以受确认方式原生提交并推送。范围只含 Git 闭环（diff 摘要 + 白名单提交 + 分步 push + 失败处理），不含文件夹搜索/预览（已移出，见 P2）。

### P2：项目工作台增强（续）

P1 之后的里程碑：文件夹筛选/搜索/预览 + 项目导入导出错误提示与冲突处理。远程控制作为横切能力单独维护（见 P3），工作线只保留入口聚合。

### P3：分发、更新与长期维护（持续）

测试/正式通道分离（已有）；**每版本"已知问题 + 回滚说明"硬发布门禁**（v4 新增）；manifest `minSupportedVersionCode`/`forceUpdate` 维护；关键异常诊断与敏感信息脱敏；横切能力（远程控制、Provider、搜索、语音、技能）的可靠性回归与本阶段一并推进。

## 研发路线图

### 近期：0.2.5 P0 收口（≈1-2 迭代）

范围（四个代码级缺口 + 三 Tab 回归）：

- 写回项目后**静默刷新** Git tab 缓存（apply 成功路径补 git status 刷新）+ APPLIED 卡加"Git 已更新"小 Chip；不自动跳转 Git tab。
- **项目上下文常驻 Chip**：项目会话时在 ChatScreen 输入栏（紧邻 ContextStatusChip）加项目名 Chip，点击进 SessionConfigDialog。
- **安装取消反馈**：`ApkInstaller` 改 `rememberLauncherForActivityResult` 结果契约，UpdateSettingsScreen 对 取消/失败/成功 各出 snackbar/内联态。
- **状态栏图标对比度**：`Theme.kt`/`MainActivity` 用 `WindowInsetsControllerCompat.isAppearanceLightStatusBars`（及导航栏）随 active ModeTheme 翻转——LIFE 暖浅→true，WORK/我的 深色→false，不看系统深色模式。
- 三 Tab 真机回归：底部三 Tab 一次点按切换、双主题过渡、重启恢复 Tab、生活会话列表无项目分组、远程入口（配对后）。

验收标准：

- 写回后无需手动跳转，再开 Git tab 即为最新状态；APPLIED 卡可见"Git 已更新"。
- 项目会话输入栏可见当前项目 Chip；生活会话列表不含任何项目概念。
- 系统安装器取消/失败/成功均有明确反馈。
- 生活=暖浅下状态栏图标清晰、工作/我的=深色下也清晰，不随系统深色模式错乱。
- 三 Tab 切换无闪烁、无回弹；主题过渡平滑；重启保持。
- 旧版本升级后数据不丢、模式迁移正确；正式通道 APK 可检查、下载、校验并拉起系统安装器。

### 中近期：P1 工作 Git 闭环（≈2-3 迭代）

范围（仅 Git 闭环）：

- **入口"待提交"视图**：Git tab 增设"待提交"视图，列出本会话累计的已评审并 apply 的写回文件 + diff 摘要（分支、ahead/behind、文件清单与增删行数）；APPLIED 卡的"查看 Git 变更"按钮跳到此处。一次"提交"动作把当前全部待提交文件**打包成一个 commit**（不碎成单文件 commit）。
- **提交信息自动生成**：按本次写回文件自动拼一句（如 `docs: 更新 README 与路线图（2 文件）`），前缀按项目配置（docs/feat/fix 等），**预填、可改、可一键提交不打字**。
- **白名单提交**：一次手机提交**只允许纳入"本轮会话中已评审并 apply 的写回文件"**；其余改动不暂存，提交前显式列出"本次只提交以下 N 个文件"。
- **提交后即问推送**：commit 成功后**紧接着**在同流程弹"推送？"（显示 ahead/behind 与分支），单独再点一次确认才推；不自动推送。commit 与 push 始终两次独立确认，绝不合并一键。
- **失败处理**：push 被拒（非快进）绝不自动 pull/merge，停止并提示"去桌面处理"；提交/推送失败均回退到"驱动桌面"兜底。

不可协商安全默认（P1 必须遵守）：

- 禁止强推（`--force`/`--no-ff`）、自动解冲突、`git reset --hard`、amend 历史、推送到受保护分支、提交 build/gradle 产物。
- 禁止 `git add -A` 或提交评审集之外的脏文件/未跟踪文件。

验收标准：

- 手机可把本轮评审通过的写回落地为一次提交，并分步推送。
- Git 操作不绕过用户确认，不默认提交无关文件，绝不强推、绝不自动解冲突。
- 移动端可在提交前评估改动规模（diff 摘要）。
- 失败有明确解释，不留隐藏部分状态。

### 中期：P2 项目工作台增强（续）（≈2-3 迭代）

范围：

- 文件夹筛选/搜索/预览：**只搜文件名/目录名 + 按类型/时间筛选**，不做文件内容全文搜索（内容检索属项目上下文/RAG，不并入文件浏览器）。
- 项目导入导出错误提示与冲突处理。

验收标准：

- 文件夹可按文件名/目录名搜索、按类型/时间筛选、预览；导入导出失败有可读错误与冲突处理。

验收标准：

- 文件夹可按类型/名称筛选、搜索、预览；导入导出失败有可读错误与冲突处理。
- 远程控制入口聚合稳定；其可靠性回归作为横切项与 P3 一并推进。

### 长期：P3 分发与维护体系（持续）

范围：

- **每版本"已知问题 + 回滚说明"硬发布门禁**：每次发布（test/prod）必须随附 `docs/releases/<version>.md`，与签名/SHA-256 校验同级；缺失则发布脚本/流程阻断。
- **回溯补齐**：0.2.4 已补 `docs/releases/0.2.4.md`（三 Tab 变更、存储模式 LIFE/WORK→三态迁移、待 0.2.5 修的状态栏对比度、回滚=侧载旧 prod 包）。
- 确认 prod manifest 的 `minSupportedVersionCode` 实际声明，让 `forceUpdate` 能拦住坏版本。
- 测试通道优先自动部署，正式通道人工确认；更新失败不破坏当前版本。
- 关键异常诊断信息保留，持续检查敏感信息脱敏。

## 优先级原则

1. 安全优先：API Key、项目文件、图片和 prompt 不应被误写、误传、误导出；Git 写入遵守 P1 白名单与安全默认。
2. 收口优先：一条线只有跑通真机验收并发布才算完成，再开下一条；功能不长期积压在 test 分支。
3. **发布前收口 checklist（v4 新增，轻量）**：每次发布前过一遍"本版本预约范围是否完成、真机回归是否通过、`docs/releases/<version>.md` 是否随附"；任一未达标不发布。不立版本号绑定硬规则。
4. 闭环优先：优先完成会话→文件→Git→更新的闭环，而不是横向增加入口。
5. 审核优先：任何项目文件写入、Git 提交和发布动作都需要用户确认。
6. 能力横切：模式只决定聚合视角，能力不因模式分裂、不重复建设。
7. 稳定优先：长文本、流式渲染、上下文压缩和更新下载优先避免卡顿和不可恢复失败。
8. 移动端优先：手机上只做高频、明确、低风险操作。

## 择机补齐 backlog（不立项、不排期）

生活线 agent 侧 RAG（L1-L4）降级至此，**仅在出现具体自用诉求时择机捡起，不作为里程碑排期**：

- L1 Agent 语料引用可溯源（`⟦A1⟧` token + 上标 + 来源卡可点 + `AgentSourceReaderScreen` + deeplink）——闭合 wiki/agent 不对称，最可能被优先捡起。
- L2 Agent 引用核验 + 原文快照防漂移（对称 `WikiCitationVerifier` 与快照回退）。
- L3 agent↔wiki 协同绑定（`Agent` 增关联 wiki 字段，切换 agent 自动带入 wiki 范围，消解 prompt 冲突）。
- L4 检索可解释面板（渲染 `AgentRuntimeDiagnostics`/`WikiRetrievalRun`）。

## 暂不做

- 用户账号、家庭成员体系和云端会话同步。
- 应用商店发布、支付、订阅和额度管理。
- 静默安装、后台无感升级和高风险系统权限。
- 自动提交、自动推送或无审核写入项目文件。**注**：P1 的"受确认手动提交/推送"不属此项——本条指无确认/自动化的提交与推送。
- 自动 pull/merge 解冲突、强推、`git reset --hard`、amend 历史。
- 复杂插件执行平台和第三方代码运行。
- 完整 IDE 式代码编辑器。
- 追赶通用 AI 客户端广度（多 Provider 矩阵、MCP 生态、PRoot Workspace、通用图片/视频生成、通用文档问答、跨设备 Web UI、WebDAV/S3 全量备份、角色卡/lorebook 等泛聊天生态）。
