# Harness APK 产品计划

日期：2026-08-02（v2，双模式叙事）

## 产品定位

Harness APK 是一个**自用为主**的移动端个人 AI 工作台，覆盖两种真实使用模式：

- **生活模式**：知识工作流。带智能体人格的对话、离线知识包（hwiki）检索与引用，随手问答、研究与写作。
- **工作模式**：项目 + 桌面端协作。项目会话、Markdown 文件变更审核与写回、Git 状态，以及手机遥控桌面 Codex 的远程控制。

产品不定位为通用聊天应用，不追求社交、账号、云端协同或应用商店分发。**底层能力是横切的**：模型/Provider、会话引擎、智能体、Wiki 知识包、搜索/语音/技能、写回/审核、远程控制、自更新均为模式无关能力，任何会话/项目内可挂载；模式层只决定首页聚合视角（生活=按会话聚合，工作=按项目聚合）。

## 双模式结构

- 首页为生活/工作双面板，左右滑动 + 顶部 Tab 切换；模式切换持久化，启动恢复上次面板。
- 生活面板：会话列表（最近会话/按项目分组视图）+ 智能体、知识库快捷入口。
- 工作面板：项目列表 + 项目工作台（会话/文件夹/Git）+ 远程控制入口卡片（未配对隐藏）。
- 双主题：生活=暖浅（奶油暖色、大圆角），工作=深科技（石墨深色、锐利小圆角），300ms 颜色过渡，全 App 统一跟随。
- 主要能力挂载点：智能体=会话内选择人格 + 设置页全局管理；Wiki 知识包=会话内检索/引用 + 设置页库管理；远程控制=全局能力，工作面板提供入口。

## 当前状态（0.2.3）

### 已具备能力

- 多会话聊天、本地保存、流式回复、图片附件、上下文压缩、联网搜索。
- 智能体体系：Agent Builder 打包人格/语料 `.hbundle`、签名校验、安装管理、删除解关联。
- hwiki 知识包体系：双史书（二十四史/资治通鉴）离线检索、Markdown 脚注引用、证据校验、版本管理。
- 项目工作台：项目会话、Markdown 文件变更计划/审核/写回、文件预览、PDF 导出、ZIP 导入导出、Git 状态面板。
- Codex 远程控制：私有 relay/bridge、配对加密、消息确认、退避重连、审批选项。
- 双模式首页与双主题（0.2.3，测试通道待真机验收）。
- APK 更新检查、分片下载、校验、安装；测试/正式通道分离。

### 主要缺口

- 0.2.3 真机验收未完成：Pager 滑动、双主题切换、模式持久化、远程入口；4 个新 androidTest 类未在设备执行。
- WORK 深色主题下系统状态栏图标对比度未联动（浅色系统设备上深色状态栏图标在深色背景下不可见）。
- 生活线：李德胜 V2 可检索 PDF 已有规划文档（`docs/superpowers/plans/2026-07-22-hwiki-*`），未实施。
- 工作线：Git 仍是状态查看，缺移动端低风险提交/推送确认流程；远程控制缺真机回归。
- 发布节奏未固化：积压功能曾长期停留在 test 分支（0.2.2 才第一次收口）。

## 阶段目标

### P0：稳定可用闭环（进行中）

在真实 Android 设备上稳定完成一次完整工作流：创建/导入项目 → 新建项目会话 → LLM 生成或更新 Markdown → 审核 diff 并写回 → 文件夹查看结果 → Git 状态 → 自更新获得新版本。双模式首页与双主题是本阶段的结构性收口。

### P1：生活模式知识工作流增强

知识包体系二期：李德胜 V2 可检索 PDF（把 PDF 引入 hwiki 构建与检索链路）；检索/引用体验打磨；智能体管理体验。生活模式作为手机端研究的默认入口。

### P2：工作模式项目工作台增强

项目页信息架构优化；文件夹筛选/搜索/预览；Git 面板移动端友好的 diff 摘要、提交前确认与低风险提交；项目导入导出错误提示与冲突处理；远程控制可靠性。

### P3：分发、更新与长期维护

测试/正式通道分离（已有）；发布前固定回归清单；manifest 向后兼容与强制更新；关键异常诊断与敏感信息脱敏；按版本维护已知问题与回滚说明。

- 旧版本升级后数据不丢、模式迁移正确。
- 正式通道 APK 可检查、下载、校验并拉起系统安装器。

### 中近期：生活模式知识工作流（李德胜 V2 可检索 PDF）

范围：

- 从 `docs/superpowers/plans/2026-07-22-hwiki-*` 规划推进 PDF 可检索实施：桌面侧解析/索引/打包，Android 侧查询/引用接入。
- 智能体 + 知识包组合体验打磨（人格负责"谁在说话"，知识包负责"本轮可以查什么"）。

验收标准：

- PDF 源能构建为签名 `.hwiki`，Android 离线可检索并返回可核验原文。
- 引用可追溯到原文位置，历史消息不因知识包升级改变来源。

### 中期：工作模式项目工作台 + 远程控制

范围：

- Git 面板移动端 diff 摘要、提交前确认、低风险提交。
- 文件夹筛选/搜索/预览增强。
- 远程控制真机回归与可靠性问题修复。

验收标准：

- Git 操作不绕过用户确认，不默认提交无关文件。
- 移动-桌面协作（远程控制）在真实网络下稳定可复现。

### 长期：分发与维护体系

范围：

- 每次发布前固定回归清单。
- 测试通道优先自动部署，正式通道人工确认。
- 关键异常诊断信息保留，持续检查敏感信息脱敏。
- 按版本维护已知问题、修复记录与回滚说明。

## 优先级原则

1. 安全优先：API Key、项目文件、图片和 prompt 不应被误写、误传、误导出。
2. 收口优先：一条线只有跑通真机验收并发布才算完成，再开下一条；功能不长期积压在 test 分支。
3. 闭环优先：优先完成会话→文件→Git→更新的闭环，而不是横向增加入口。
4. 审核优先：任何项目文件写入、Git 提交和发布动作都需要用户确认。
5. 能力横切：模式只决定聚合视角，能力不因模式分裂、不重复建设。
6. 稳定优先：长文本、流式渲染、上下文压缩和更新下载优先避免卡顿和不可恢复失败。
7. 移动端优先：手机上只做高频、明确、低风险操作。
