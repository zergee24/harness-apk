# Harness APK 产品计划

日期：2026-08-07（v5，未来三个月路线图）

规划周期：2026-08-08 至 2026-11-07

> v5 取代 2026-08-04 的 v4。v4 中的 P0 修复、P1 Git 闭环核心和 P2 文件夹搜索已经进入 `test`；本版不再沿用旧 P 编号排未来工作。外部对标依据见 `docs/agent-harness-top50-benchmark-2026-08-07.md`。

## 1. 产品定位

Harness APK 是**个人 Agent 系统的移动控制与记忆层**：

- 手机负责捕获意图、选择上下文、查看最新进展、处理审批和验收结果。
- M4 Mac 上的 Codex 负责代码、文件、测试、构建等重执行。
- `.hagent` 负责人物身份与表达方式。
- `.hwiki` 负责可检索、可引用的事实来源。
- 项目 Markdown 与 Git 负责长期事实、产物和版本历史。

Harness 不再以“比通用 AI 客户端多几个功能”为目标，也不把 Android 做成缩小版 IDE 或通用 Agent 沙箱。

一句话主张：

> 在手机上十几秒发起正确的工作，随时看懂 Agent 做到哪一步，只在真正有风险时确认，并让结果回到项目。

## 2. 个性化使用链路

### 2.1 主链路

```text
语音 / 分享 / 输入
        ↓
选择或自动恢复正确项目、会话、Agent、Wiki
        ↓
轻任务在 Harness 完成 / 重任务交给 Mac Codex
        ↓
离开 App，后台继续
        ↓
通知或活动入口展示最新状态、阻塞和审批
        ↓
查看原文、Diff、测试或 Git 证据
        ↓
经审核沉淀到项目 Markdown，必要时提交和推送
```

### 2.2 生活链路

- 从生活首页继续最近会话，或用语音、分享快速新建。
- 会话可选择一个 `.hagent` 身份，并在允许的多个 `.hwiki` 中自动检索。
- 默认只展示当前最新过程行；需要时再展开完整过程和来源。
- 有长期价值的回答可以显式沉淀到某个项目，但普通闲聊不制造文件。

### 2.3 工作链路

- 从项目进入会话、文件、Git 或该项目关联的 Mac Codex 任务。
- 手机不要求输入 Mac 绝对路径，不要求理解 app-server 事件。
- Codex 可以在后台继续；手机只展示目标、最新进度、待处理事项和可验证结果。
- 项目写入继续使用现有 Markdown 提案、Diff 审核、Apply、白名单 Commit、分步 Push 闭环。

## 3. 核心对象与边界

| 对象 | 职责 | 关键边界 |
| --- | --- | --- |
| Project | 长期目标、Markdown、文件和 Git 的归属 | 是唯一长期工作归属，不新增 Workspace / Notebook 模式 |
| Conversation | 用户与模型连续交互 | 可以归项目，也可以是生活会话；与 Markdown 保持弱关联 |
| Agent | 决定“谁在说话” | 全局安装，按会话精确版本使用，不归项目所有 |
| Wiki | 决定“可以查什么” | 全局安装，会话多对多授权，系统只能在授权范围内自动选择 |
| Run | 一次本地生成或远程 Codex 执行 | 是内部执行对象，不新增用户可见顶层模式 |
| Artifact | 回答、引用、文件、Diff、测试结果或 Git 结果 | 必须记录位置和来源，不能把 Mac 文件伪装成手机本地文件 |
| Context Snapshot | Run 发起时的项目、会话、Agent、Wiki、模型和附件快照 | 发起后不可被后续设置静默改写，保证可复现 |

项目与 Mac 工作区只建立**弱绑定**：项目不复制或拥有 Mac 工作区，解绑不删除任何一端文件。三个月内不做隐藏双向同步。

`.hagent` 的关系记忆只保存跨项目仍然成立的称谓、表达偏好和关系变化；项目决策、进度、文件与任务事实只能进入对应项目上下文。两类记忆检索和写入分开，避免人物关系把不同项目串在一起。

## 4. 当前基线

基线版本为 `0.2.5` test 预验证阶段，代码口径截至 `test` 分支提交 `1472557`。

### 4.1 已具备能力

- 三 Tab：生活 / 工作 / 我的；生活暖浅、工作和我的深色主题。
- 多会话、本地保存、流式回复、后台生成、队列转向、失败恢复、图片输入和联网搜索。
- 思考过程默认中文；折叠态展示最新非空行，支持展开完整过程与来源。
- `.hagent` 本地构建、签名导入、人物资料检索、关系记忆和来源记录。
- `.hwiki` 本地安装、版本管理、目录浏览、原文搜索、会话多对多挂载、自动路由、引用核验和原文回跳。
- 项目会话、`context.md`、Markdown 变更提案、Diff 审核、文件浏览、PDF / ZIP、文件名与路径搜索。
- Git 状态、白名单提交、自动提交信息、提交后单独确认推送、非快进禁推。
- 私有 Relay + Mac Bridge + Codex app-server 远程线程、转向、停止、审批和推送提醒。
- test / prod 更新通道、分片下载、SHA-256 校验、系统安装器和发布说明门禁。

### 4.2 已核实的核心痛点

1. **捕获仍慢。** 语音设置和按钮已经存在，但当前点击只提示“暂未接入可用的语音输入方案”；Android 分享入口只处理 `.hbundle` / `.hwiki` 包。
2. **项目与 Codex 割裂。** 新建远程线程仍要求手输 Mac 绝对路径；远程线程没有 `projectId`，无法从项目自然继续。
3. **长任务可见性不足。** 本地生成和远程任务分散在不同页面；远程状态偏内存态且围绕当前选中线程，原始 item 类型和 JSON 不适合手机阅读。
4. **审批还只是卡片。** 审批缺少稳定的跨页面恢复、风险分级和影响范围；“总是允许”的作用域不够直观。
5. **项目有上下文文件，但缺少连续记忆体验。** `context.md` 是正确的事实根，但用户仍需手工维护，项目历史会话也不能按需检索并回链。
6. **完成结果容易留在聊天或远程时间线。** 回到项目仍需要用户重新概括，破坏“会话驱动 Markdown”的主张。

## 5. 三个月目标

### 5.1 北极星

**每周完成的“可信闭环”数量**：一次意图从手机发起或接力，经过可恢复执行和必要审批，最终形成已核验回答、项目 Markdown 或 Git 结果。

不采用 DAU、消息数或 Token 消耗作为主指标。这个产品自用为主，价值在完成高质量闭环，不在增加聊天时长。

### 5.2 三个产品押注

1. **零摩擦捕获**：语音、分享和一键继续，把意图送进正确上下文。
2. **跨端连续任务**：手机和 Mac 共享同一个任务事实，任务可离开、恢复、转向和审批。
3. **结果回到项目**：有价值的结论经审核进入 Markdown / Git，而不是滞留在消息历史。

### 5.3 不可协商原则

- 不新增第四个底部 Tab，也不新增 Wiki / Agent / 任务顶层模式。
- 不自动扩大 Agent、Wiki、文件或工具权限范围。
- 不自动写项目文件，不自动 Commit，不自动 Push。
- 不在锁屏通知中直接批准写文件、执行命令、联网或 Git 操作。
- 不用隐藏同步掩盖手机项目与 Mac 工作区的差异。

## 6. 三个月路线图

### M1：十几秒进入正确上下文

周期：2026-08-08 至 2026-09-07

目标：减少“打开 App、找入口、重复解释”的时间，先把移动端输入做到真正可用。

#### M1.1 系统语音输入闭环

- 接通 Android `SpeechRecognizer` 或系统语音识别 Activity，默认中文，可在设置中切换语言。
- 转写结果默认填入输入框，不自动发送；保留现有草稿并按换行合并。
- 明确显示录音中、识别中、失败和权限状态；失败不清空草稿。
- 默认不保存原始音频，不引入云端 STT Provider。

#### M1.2 Android 分享入口

- 支持从浏览器、相册、文件管理器分享文本、URL、图片和普通文件到 Harness。
- 文本、URL、图片进入“发送草稿”；普通文件只能导入目标项目，不直接塞入模型上下文。
- 只出现一个轻量目的地面板：最近会话 / 最近项目 / 新会话；默认预选最近合理目标，但发送或导入仍需一次确认。
- 记住上次目的地，不创建“收件箱”顶层页面。

#### M1.3 一键继续与全局搜索

- 生活首页优先展示最近活跃会话；工作首页优先展示最近项目和进行中任务。
- 增加一个全局搜索入口，检索会话标题、正文、来源标题和项目名称，结果直接定位到消息或项目。
- 搜索使用本地索引，不上传完整历史；首期不做向量搜索。

#### M1.4 单一上下文条

- 会话输入区把项目、Agent、Wiki 范围和模型压缩成一条可点击摘要，例如：`CRM · 李德胜 · 自动 2 库 · GPT`。
- 默认不要求用户逐项确认；只有范围变化时展开设置。
- 每次发送保存 Context Snapshot，后续设置变化不改写旧消息事实。

#### M1 验收

- 从 Android 分享文本到发出消息，正常路径不超过 2 次确认。
- 从点击麦克风到转写进入输入框，用户无需进入设置或选择 Provider。
- 冷启动后 2 次点击内可恢复最近会话或项目。
- 分享、语音识别失败和进程重建后草稿不丢。
- 320dp 宽度、字体缩放 1.3 下，上下文条和输入区无重叠。

### M2：一个任务跨手机与 Mac 连续运行

周期：2026-09-08 至 2026-10-07

目标：把现有远程控制从“能操作 Codex”升级为“能可靠监督一个长期任务”。

#### M2.1 项目与 Mac 工作区弱绑定

- 新增 `ProjectRemoteBinding(projectId, hostId, cwd, repositoryFingerprint)`。
- 在项目中绑定一次 Mac 工作区；后续从项目发起 Codex 任务不再输入绝对路径。
- 绑定前展示主机、路径、Git remote / repo 指纹；指纹变化时暂停并要求重新确认。
- 解绑只移除映射，不删除项目、Mac 文件或 Codex 线程。

#### M2.2 可持久化远程任务快照

- 本地保存 Thread / Turn、项目、目标、状态、最后事件序号、审批和完成摘要。
- Bridge 与 App 使用幂等请求 ID 和事件序号；断网或进程被杀后可以从最后确认位置恢复。
- 不强行合并本地聊天执行器和 Codex app-server，只建立统一的 Activity 读模型，控制重构范围。

#### M2.3 统一活动与审批入口

- 在生活 / 工作首页顶栏提供同一个活动图标；有待审批时显示数量，无事件时不占页面空间。
- 活动页只分“需要我处理、进行中、最近完成”，不增加复杂状态 Tab。
- 本地生成和远程 Codex 都进入该读模型，但保留各自执行内核和详情页。
- 通知点击必须打开精确任务；通知允许“查看”“拒绝”“停止”，高风险批准必须解锁后在详情内完成。

#### M2.4 手机可读的任务时间线

- 折叠态只显示最新一行状态，沿用当前思考过程交互。
- 事件翻译为目标、查找、修改、测试、等待审批、完成或失败，不在主视图展示原始 JSON 和内部 item 名称。
- 审批卡展示动作、对象、工作区、影响范围和风险级别。
- “总是允许”只允许作用于当前项目 + 当前工具 + 当前 Run 的低风险动作；文件写入、命令、联网和 Git 不提供跨 Run 永久放行。

#### M2.5 结构化完成卡

- 完成卡至少包含：一句结果、变更文件、测试状态、Git 状态、未解决问题和继续入口。
- 文件、Diff、终端证据和错误详情按需展开。
- 失败卡说明“发生了什么、已保留什么、下一步能做什么”，只给一个主恢复动作。

#### M2 验收

- 从项目发起已有绑定的 Codex 任务不超过 3 次点击，不输入路径。
- App 被系统杀死、网络中断 10 分钟、Bridge 重连后，任务状态和未决审批不丢失、不重复执行。
- 所有待审批都能从通知和活动入口到达同一状态；重复点击不会重复批准。
- 用户在手机上能完成“发起 -> 离开 -> 通知 -> 查看 -> 补充方向 -> 验收”的完整任务。

### M3：结果成为项目记忆和可继续产物

周期：2026-10-08 至 2026-11-07

目标：闭合“会话 / Codex 任务 -> 项目 Markdown -> Git”，减少下次重新解释项目背景。

#### M3.1 项目级历史检索

- 在项目会话发送前，按需检索该项目的 `context.md`、Markdown 文件和历史项目会话。
- 首期使用本地 FTS、标题、路径和时间排序，不在手机运行 embedding 或 GraphRAG。
- 注入上下文必须带来源类型和稳定定位；回答可回跳到消息或项目文件。
- 检索范围严格限制在当前项目，生活会话和其他项目不参与。
- Agent 关系记忆可以影响表达方式，但不能作为项目事实来源；涉及项目事实时必须回到项目 Markdown、项目会话或任务证据。

#### M3.2 一键“沉淀到项目”

- 助手回答和远程完成卡提供同一个“沉淀”动作。
- 系统根据内容建议更新 `context.md` 的项目目标 / 关键决策 / 当前状态 / 待跟进，或创建研究记录、会话摘要、验收报告。
- 建议只是 Markdown 变更提案，继续走现有 Diff 审核和 Apply；不静默写文件。
- 引用 Wiki、Agent 资料或历史消息时，保留可读脚注和来源定位。

#### M3.3 项目上下文刷新建议

- 只有出现稳定决策、状态变化或明确待办时生成候选，不把临时讨论、模型推理和未验证事实写进 `context.md`。
- 每个完成任务最多展示一次轻量建议；用户忽略后不反复打扰。
- 已应用内容再次出现时去重，不制造重复段落。

#### M3.4 复用现有 Git 闭环

- Apply 后继续使用白名单 Commit 和独立 Push 确认。
- Mac 产物默认仍留在 Mac，完成卡明确标记位置；跨设备传输必须是显式导入、Git Fetch 或另一次受控任务。
- 不实现隐藏文件同步、自动 Pull / Merge、自动解冲突或强推。

#### M3.5 本地评测与复盘

- 建立不少于 20 条黄金链路：生活问答、Agent + Wiki、项目继续、远程任务、审批恢复、Markdown 沉淀和 Git 失败。
- 每周本地生成一页闭环报告：发起数、完成数、恢复失败、审批遗漏、平均发起步骤和未沉淀任务。
- 报告留在本机，不接入第三方行为分析 SDK。

#### M3 验收

- 用户再次进入项目会话时，可以直接问“上次决定了什么”，回答带消息或文件来源。
- 一次手机发起的 Codex 任务可生成完成卡，并经一次 Diff 审核沉淀为项目 Markdown。
- 项目上下文不跨项目泄漏，旧引用不因文件或 Wiki 更新静默漂移。
- 项目写入、Commit、Push 仍分别需要明确确认，拒绝后任务状态可继续理解。

### 三月范围熔断

- M1 的语音、分享和 Context Snapshot 是必达项；若第 4 周主链路仍不稳定，全局搜索顺延。
- M2 的弱绑定、Run 持久化和审批可达是必达项；若恢复测试未通过，时间线视觉优化和更丰富的完成卡顺延。
- M3 的项目检索带来源、审核后沉淀是必达项；若闭环未通过，每周报告和高级排序顺延。
- 不因日历进入下一个月就并行堆功能。任何新增方向必须替换同等工作量的现有项，不能直接追加。

## 7. 极致移动体验基线

### 7.1 首页只回答“下一步做什么”

- 生活首页优先继续会话和快速输入，不展示功能说明卡。
- 工作首页优先最近项目、活动任务和待审批，不展示远程协议或主机技术信息。
- Agent、Wiki、模型和设置保留在二级管理入口，不争夺首页注意力。

### 7.2 单手操作

- 高频动作位于底部输入区、任务完成卡或通知深链。
- 图标按钮使用熟悉图标和无障碍标签；触控目标不小于 48dp。
- 不在正常路径要求输入绝对路径、ID、指纹或 JSON。

### 7.3 渐进披露

- 思考、工具、检索和远程执行默认展示最新一行。
- 完成后默认展示结果、变更和验证；原始日志、完整来源和技术详情按需展开。
- 一个页面只保留一个主动作，失败状态只给一个推荐恢复动作。

### 7.4 性能与后台

- 输入提交后 100ms 内必须出现本地排队态，不等待网络返回。
- 本地页面切换目标 p95 小于 200ms；冷启动到可交互目标 p95 小于 1.5s，以目标真机实测为准。
- 没有活跃任务时不常驻前台服务；远程完成优先使用加密 Push 唤醒。
- 所有草稿、Run、审批和 Context Snapshot 都必须跨进程恢复。

### 7.5 信任

- 来源、工作区、文件位置和版本必须可见。
- 读取可以自动，写入和外部副作用按风险确认。
- 任何“自动”都只能在用户已授权范围内缩小选择，不能扩大权限。

## 8. 指标

| 指标 | M1 目标 | M2 目标 | M3 目标 |
| --- | --- | --- | --- |
| 捕获到发起中位时间 | 小于 15 秒 | 保持 | 保持 |
| 恢复最近工作所需点击 | 不超过 2 次 | 不超过 2 次 | 不超过 2 次 |
| 远程任务恢复测试通过率 | 建基线 | 100% 黄金故障用例 | 持续 100% |
| 待审批可达率 | 建基线 | 100% | 100% |
| 无审核项目写入 / 自动 Push | 0 | 0 | 0 |
| 长任务形成可验证完成卡 | 不适用 | 100% | 100% |
| 有价值结果可沉淀到项目 | 现状基线 | 设计验证 | 100% 支持 |

自用阶段不追求虚假的统计显著性。每周看真实失败案例，优先修复阻断主链路的前三项。

## 9. 研发与发布节奏

### 第 1-4 周

- 第 1 周：语音识别、草稿恢复、权限与失败状态。
- 第 2 周：Android 分享草稿和项目文件导入。
- 第 3 周：全局搜索、一键继续、单一上下文条。
- 第 4 周：真机、320dp、字体 1.3、后台和升级回归。

### 第 5-8 周

- 第 5 周：项目与 Mac 工作区绑定、协议兼容设计。
- 第 6 周：远程 Run 持久化、事件序号和恢复。
- 第 7 周：活动入口、审批状态机和通知深链。
- 第 8 周：结构化时间线、完成卡、断网与进程死亡回归。

### 第 9-12 周

- 第 9 周：项目历史 FTS 和来源回跳。
- 第 10 周：沉淀提案、`context.md` 刷新建议和去重。
- 第 11 周：远程完成卡到项目 Markdown / Git 闭环。
- 第 12 周：20 条黄金链路、性能门槛、已知问题与回滚说明。

每个阶段只有在 test 真机完成主链路后才进入下一阶段。每次发布继续要求：

- `docs/releases/<version>.md`。
- 单元测试、关键 Android 测试和 Remote Go 测试通过。
- 已知问题、回滚路径和数据迁移说明明确。
- 不自动 Push 产品代码；发布与远端推送仍单独确认。

## 10. 三个月明确不做

- 第四个底部 Tab、独立 Agent 模式、独立 Wiki 模式或任务模式。
- Android 本地 MCP、PRoot、Docker、任意 Shell 或第三方代码执行。
- 多 Agent 团队、并行 Agent 管理面板和可视化 Workflow 画布。
- Provider 大全、模型市场、角色卡市场、Skill 商店。
- 通用 PDF / Office / 音视频 RAG；文件只服务项目或桌面构建器。
- Android embedding、向量数据库和 GraphRAG 构建。
- 自动计划任务、浏览器代操作、邮件 / 日历 / IM 连接器。
- 账号体系、云会话同步、Web 端和多人协作。
- 手机与 Mac 的隐藏双向文件同步。
- 自动写文件、自动 Commit、自动 Push、自动 Pull / Merge、强推和自动解冲突。

## 11. 三个月后再评估

只有前三个月北极星闭环稳定后，才按真实自用频率评估：

- 桌面 Skill / Agent / Wiki 的签名远端目录与推荐安装。
- 项目内可信计划任务和每日简报。
- Android 小组件或快捷设置磁贴。
- 云端 STT 作为系统语音识别的可选降级。
- 更完整的跨设备 Git handoff，而不是通用文件同步。
- 项目级向量索引，但仍由桌面离线构建。
