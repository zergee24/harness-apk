# 0.2.6 已知问题与回滚说明（测试通道预验证版）

> 本版为 P1 工作线 Git 闭环**核心**（白名单提交 + 提交后推送确认）的测试通道预验证版，用于真机回归；正式通道尚未发布。
>
- versionName：`0.2.6`（test 通道显示 `0.2.6-debug`）
- versionCode 基础：`2000000`（实际构建号 = 基础 + GitHub run number）

## 本版本主要变更（P1 Git 闭环核心）

1. **"待提交"白名单提交**：项目工作台 Git tab 新增"待提交(N)"入口，列出"本轮会话已评审并 apply 的写回文件"（由 `container.projectAppliedPaths` 记录、与当前工作区改动取交集），支持逐文件增删行数摘要。
2. **自动预填提交信息**：按改动文件类型推导前缀（全 Markdown → `docs:`，否则 `chore:`）+ 文件数与文件名，预填、可编辑、可一键提交不打字。
3. **只暂存白名单路径**：新增 `GitEngine.stagePathsAndCommit`，只 `git add` 指定路径，**不执行 `git add -A`**；其余工作区改动保持不暂存。
4. **提交后推送确认**：提交成功紧接着弹"推送到远端？"，显示分支/领先/落后；落后（非快进）时禁用推送并提示"去桌面处理"，**绝不自动 pull/merge**。
5. **改动统计**：新增 `GitEngine.diffStat`，按文件给出相对 HEAD 的增删行数。

## 安全约束（P1 已落地）

- 禁止强推、自动解冲突、`git reset --hard`、amend；非快进不自动拉取。
- 一次提交只纳入本轮已 apply 的写回文件白名单；其余不暂存。

## 待真机回归（发布前必须）

- "待提交"列表在真实写回后正确出现，只含本轮 apply 的文件。
- 提交信息预填与一键提交流程；提交后推送确认弹窗与非快进禁用推送。
- `stagePathsAndCommit` 只提交白名单、不动其它改动（已有 JVM 测试覆盖，仍需真机确认 UX）。
- diffStat 增删行数显示正确（已有 JVM 测试覆盖）。

## 已知限制

- 仅覆盖 Markdown 写回场景（新增/修改）；删除类变更未走 `git rm`，暂不在白名单提交支持范围。
- 提交后 `gitStatus` 的 aheadCount 可能在推送确认弹窗渲染瞬间略滞后（refreshGitState 异步），behindCount 不受影响，推送启用判断安全。
- 回滚同 0.2.4/0.2.5：无应用内降级，侧载旧 prod 包（同包名、同通道固定签名）。
