# Harness APK 0.4.0

> 发布状态：**候选，自动化 PASS；发布 NO-GO（MANUAL PENDING）**。最终工作树全量 Android/Go、完整隔离脚本与 20 条确定性黄金链路均已通过；荣耀真机、真实 Relay/Mac/Codex、TalkBack 和真实 Git Commit/Push 人工 Gate 尚未关闭。

## 发布范围

0.4.0 对应 M3“项目记忆闭环”：在本机把当前项目 Markdown、项目消息和冻结的 Remote Run 证据统一索引为可审计来源；回答引用保存不可变快照；Assistant、Remote Completion 和显式文件变更统一进入持久 Draft、Diff、Apply、Commit、Push 分步流程。

M2、M3 按序合并并完成合并态验证后，`test` 的默认 Gradle `versionName` 升级为 `0.4.0`；Debug 包与 test 更新清单展示为 `0.4.0-debug`。基础 `versionCode` 仍为 `2000000`，测试通道由发布流程叠加 GitHub run number 保证递增。

本版本不新增记忆 Tab、知识库 Dashboard、向量数据库、云同步、自动 Pull/Merge、自动解冲突、自动 Commit 或自动 Push。

## 数据与协议

- Room 从 22 升至 23，扩展唯一 `local_search_fts` 的文档元数据，并增加 Retrieval Run、Evidence Snapshot、Draft Origin、Context Fact 去重和 Remote completion 冻结表。
- 原 M1 搜索、Agent/Wiki、Context Snapshot V2 和 M2 Remote Run 数据必须原位保留。
- Remote completion 使用带 `schemaVersion` 的 v2 加法 envelope；Wire v1 和 Logical Event v1 保持不变。
- 旧 v1 completion 可读取但标记 `legacy/unverified`，不得由后续 Snapshot 静默改写。
- Bridge `host.status` payload 使用加法 `schemaVersion: 1` capability 列表；M2 基线为 `workspace.candidates.v1`、`run.lifecycle.v1`、`logical-replay.v1`，M3 增加 `completion-evidence.v2`、`turn-command-idempotency.v1`。旧 APK 可忽略新增 payload；新 APK 缺少所需 capability 时 fail closed，只保留 legacy history。
- Remote 会话列表和详情页统一显示执行中、等待审批、等待回复、已完成、失败、已中断或状态未同步；Bridge 通过加法 `thread-execution-status.v1` 返回最新 Turn 状态。Android 只对可见的活跃卡片每三秒懒轮询，进入终态后自动停止。
- Relay 仍只转发加密消息；0.4.0 不新增 Relay 文件传输、Mac 文件自动导入或远程写回协议。

## 失败恢复

- 索引失败保留 dirty 状态，普通聊天仍可继续；No Match 不注入项目事实。
- Retrieval Run 和 Evidence Snapshot 一旦用于发送即不可被重建索引覆盖。
- Draft 在 Room 中恢复；Apply 前重新核对 `baselineSha256/expectedAbsent`，冲突保留 Draft 和当前文件。
- Bridge 只接受首次冻结终态；缺失或不可验证 ledger 时保持对账中，不从后来变化的 Mac 工作区重建证据。
- Bridge 在观察到终态后持久记录 reconciliation；启动、WebSocket 重连和 `sync.resume` 会重试本地对账。ledger 已冻结而 journal 缺事件时，以稳定 event ID 补发，不覆盖首次终态。
- legacy `turn.start` 以 `CommandID`、否则 `RequestID` 持久去重。App Server 已成功而 TurnID 解析/route 落盘失败时返回 `UNKNOWN/RECONCILING` 且 `retrySafe=false`，后续只重试本地 route 回填，不再次创建 Turn。
- 继续历史会话时若当前 App Server 尚未加载该 Thread，Bridge 会在明确的 `thread not found` 后先读取不含 Turns 的元数据。常规记录继续 `thread/resume` 原 threadId，并以同一 `clientUserMessageId` 安全重试一次 `turn/start`；超过直接恢复边界的大会话改走懒续聊：分页读取最近 8 个 Turn，只提取用户/Codex 文本且总量不超过 24 KiB，以 `untrusted additionalContext` 注入同工作目录的新 Thread，再发送用户本次原始输入。Bridge 持久记录物理 Thread 链，Android 列表仍只展示一个沿用原标题的逻辑会话；上翻到续聊边界时才懒加载原 Thread 历史。成功、明确失败和不确定结果仍分别显示为已送达、发送失败和发送结果待确认，不再永久停留在“发送中”。
- Git/workspace 证据捕获失败必须记录为 `UNVERIFIED` 并附原因，不能伪报 `CLEAN`。

## 发布顺序与运维检查

1. 冻结候选版本和日志目录；确认 Android 最终工作树与 Bridge SHA 一致，不混用早期 targeted 结果签署。
2. 停止 Bridge launch agent，按权限完整备份 `~/.harness-remote`，不得只复制 `bridge.json`。
3. 先部署理解 state v2、terminal ledger 和新 capability 的 Bridge。旧 APK 会忽略加法字段；确认 `host.status`、一次 Run、一次 approval、断线后 `sync.resume` 正常。
4. 再安装使用 Room 23 的 0.4.0 候选 APK；自动化已通过，继续执行验收台账中的人工 Gate。
5. 只有人工 Gate 签署后才能把发布状态从 `NO-GO` 改为通过。禁止仅凭 `versionNameOverride=0.4.0` 产物或模拟器自动化对外分发。

发布前必须保留以下证据：最终 JVM/assemble、全量 connected、40 Query 指标、JVM/Room 10k×10 p95、Go race/vet/build、脚本 cleanup，以及真实 Relay/Mac/荣耀真机和 Git Commit/Push 人工记录。

## 回滚边界

- 旧 schema 22 APK 不能直接安全打开 Room 23。Android 回滚包必须包含读取 23 的兼容迁移并关闭 M3 feature gate；禁止通过清应用数据回滚。
- 回滚不得删除 Evidence Snapshot、Remote Journal、completion ledger、Draft 或用户项目文件。
- Bridge 回滚版本必须能忽略 completion v2 未知字段并保留已有 ledger；不能退回“按当前工作区重建完成证据”的实现。
- 如果只需停止发布，应保留 0.4.0 数据和文件，关闭入口/后台索引，再用兼容构建恢复；不要降库、自动合并 Git 或强推。
- Bridge 回滚必须整目录处理 `~/.harness-remote` 的同一恢复集：`bridge.json`、`logical-events.log`、`commands.json`、`routes.json`、`workspaces.json`、`terminal-runs.json`。禁止混搭不同时间点的单文件、手改 completion JSON/hash 或只删除 journal/ledger。
- 若新版 Bridge 已写入 terminal ledger schema v2、终态 reconciliation 或 Turn 幂等 command record，回滚目标必须理解并保留这些记录；不满足时保持当前 Bridge，关闭移动入口，而不是启动旧二进制试写状态。
- 回滚后先验证 capability 降级行为和 `sync.resume`；缺少 M3 capability 时 Android 必须隐藏/禁用对应入口但仍允许 legacy history，不能假装支持 completion v2。

## 已知限制

- PDF、Office、媒体正文、隐藏目录、`.hagent`、`.hwiki` 和二进制文件不进入项目索引。
- 单 Markdown 文件正文上限 2 MiB，单项目本轮扫描正文上限 50 MiB；超限来源保留可见文件但不注入回答。
- Mac-only 文件不会伪装成手机本地文件，需要显式 Git Fetch 或用户确认的受控导入。
- 旧 v1 completion 没有冻结 ledger 时只能显示 legacy/unverified，不能补造可验证 evidence。
- 去重边界依赖稳定命令身份；调用方若同时更换 `CommandID` 和 `RequestID`，Bridge 会将其视为新命令。崩溃若发生在 App Server 成功但结果尚未持久化的极窄窗口，Bridge 会保持 UNKNOWN 并阻止重复执行，但不能自动恢复 TurnID。
- terminal ledger 在 rename 成功但目录 Sync 报错时会保留首次终态并停止继续写入；需停止 Bridge、完整备份状态目录并重启兼容版本排查，不得覆盖或手修 ledger。
- 大会话懒续聊只把最近 8 个 Turn 内可读的用户/Codex 文本作为模型上下文，并受 24 KiB 上限约束；命令输出、文件变更和推理明细不会复制。原会话完整保留，手机可从同一逻辑会话继续分页上翻，但新物理 Thread 的模型上下文不等价于恢复全部历史。需要更早决策时，Codex 应核对当前工作区或向用户确认，不得假装拥有被省略的上下文。
- 自动化不能复现荣耀真机 OEM/锁屏 Push、真实 Relay/Mac Bridge/Codex app-server、TalkBack 人工听读和真实远端非快进 Push；这些仍是发布前人工 Gate。
- 文件来源回跳当前定位到文件或消息；文件内 Heading 以 Sheet 文本显示，尚未提供编辑器内精确锚点滚动。
